# Bug Fixer

## 适用场景

- 报错、异常、测试失败、构建失败。
- 行为和预期不一致。
- 最近改动造成回归。

## 输入要求

- 错误信息、复现步骤、期望行为和实际行为。
- 如果用户没有提供，先从代码、日志、测试或命令中收集证据。

## 执行流程

1. 记录症状和已知事实。
2. 尝试复现或收集最接近的证据。
3. 定位相关代码路径和最近变更。
4. 提出最小假设并验证。
5. 做最小修复。
6. 运行回归验证。
7. 如果问题属于可复用经验，更新项目的 troubleshooting 文档或本项目的 memory。
8. 总结根因、修复和测试结果。

## 禁止事项

- 不先猜测然后大改。
- 不用掩盖错误代替修复根因。
- 不删除测试来让结果变绿。
- 不在没有证据时宣称找到根因。
- 不把环境、编码、端口、配置漂移等系统性问题只当作一次性错误处理。

## 输出格式

```markdown
# Bug Fix Report

## 症状
## 复现或证据
## 根因
## 修复
## 验证
## 记录更新
## 剩余风险
```

## 验证标准

- 至少有复现、日志、测试失败或代码证据之一。
- 修复范围最小。
- 回归验证覆盖原问题。

## 停止条件

- bug 修复并验证完成。
- 无法复现且缺少继续判断的关键证据。
